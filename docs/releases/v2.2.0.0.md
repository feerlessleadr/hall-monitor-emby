## Hall Monitor plugin 2.2.0.0

The status now reports every limit a user has, not just the one closest to running out. Install over 2.1.0.0; nothing in your settings changes. The Embidextrous app 0.9.0 uses this to alert at a percentage of any limit, so update the plugin first, then the app.

### What's new
- **A `Limits` list in the status.** For each enabled limit (daily, weekly, monthly, yearly) it gives the allowance (the limit plus any extra time), what was counted, what is left, and the whole percent used (100 means the limit is reached). It is in the live push, `Public/Status`, and the admin `LimitedUsersStatus`. `ApiLevel` is now 4.
- **Why:** before, a weekly limit at 90% was invisible while the daily limit had less time left, so an app could not warn about it. Now it can.
- Nothing else changes. `LimitingPeriod`, `SecondsRemaining` and `LimitingAllowedSeconds` still describe the limit closest to running out, so older apps keep working.
- Under the hood, the limit arithmetic moved into one small, unit-tested class that both the list and the closest-limit fields use, so they cannot disagree.

### Checked
- 21 unit tests (10 new); the regression suite on a test server passed 70 of 70 twice, plus 69 of 69 on a full run, with three new checks for the `Limits` field.
- Live: a test child with a 2-minute daily and a 1-hour weekly limit played a track through real session reports. Both limits were listed (through both the admin route and the public key route), and the daily percent climbed from 12% to 100% as the plugin counted the playback.

### Known limits
- A weekly or monthly limit nearing its end was not tried live (it cannot fill in a few minutes). The percent arithmetic is unit tested for every period.
- The plugin's own dashboard page does not show the per-limit list yet.
- The regression suite's lockout check locks the Public API key for 5 minutes, so run the suite again only after restarting Emby (or use `-SkipLockout`).
